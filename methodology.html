Methodology

The standards behind every result on this site.

Git Flow

Development follows a strict branch-based workflow to ensure production stability and verifiable version history:

  • Main Branch Continuity: The main branch remains strictly deployable. No direct commits are permitted.
  • Feature Isolation: Every technical update, algorithm refinement, or data pipeline modification is executed on an isolated feature branch branched directly from main.
  • Pull Request Documentation: Code changes are merged via pull requests detailing the specific problem addressed, architectural decisions made, and regression test logs.
  • Commit Atomicity: Commit history is kept atomic and descriptive, mapping changes back to core project criteria.

Data Cleaning Standards

Raw datasets from LLM generation traces or MLS real estate feeds undergo a rigorous multi-stage preprocessing pipeline before downstream evaluation:

  • Schema Enforcement: Raw inputs are validated against strict types and expected field schemas to prevent downstream malformed payloads.
  • Discrepancy Categorization: Data errors are explicitly categorized rather than excluded blindly. In text assessment sets, responses are coded into binary vectors (1 for correct, 0 for incorrect) based on specific answer key alignments.
  • Noise Mitigation: Prompts and text data are stripped of formatting artifacts and machine-generated noise while preserving instructional context and edge cases.
  • Feature Extraction: Structural attributes (such as total living area in valuation models or token lengths in generation prompts) are isolated systematically under repeatable mathematical transforms.

Testing Standards

Validation protocols prioritize operator-level isolation and exact error metrics over generalized qualitative summaries:

  • Baseline Dominance Checks: Evaluation scripts sweep parameters (e.g., budgets N = 2 to 5 or Dirichlet alphas) to confirm new strategies strictly dominate independent baselines across 100% of tested domains.
  • Statistical Rigor: Performance models utilize specific interrater agreement measures—including Cohen's Kappa, precision, recall, and F1 scores—to map AI performance directly against human baselines.
  • Smoke Testing Pipelines: Technical codebases maintain small dry-run validation sets (_smoke folders) containing condensed verification files to run quick sanity checks before executing full-scale trial datasets.
  • Error Mass Tracking: Pipelines track exact error mass distributions, calculating Pearson correlation metrics to monitor behavior under varying concentrations.
